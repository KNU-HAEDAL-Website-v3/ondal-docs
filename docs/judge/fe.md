# 자동 채점 화면 설계

> 결정은 [design.md](design.md), 계약은 [api.md](api.md). 화면 원칙: **출제는 표 하나로 끝, 학생 결과는 배지 하나로 읽힌다**

## 1. 출제 - 과제 폼(`AssignmentFormPage`)의 "자동 채점" 섹션

- 위치: 기존 과제 폼(제목·설명·차시·마감·문제 번호) 아래, 접힌 섹션 "자동 채점" - 토글 켜면 펼침. 과제 저장(#16/#17 PUT)과 채점 설정 저장(#48)은 **별도 요청**이지만 FE 는 "저장" 버튼 하나로 순서대로 호출(과제 먼저 → 채점 설정). 새 과제는 과제 생성 응답의 id 로 이어서 #48
- 테스트케이스 표: 열 = `#` · 입력 · 기대 출력 · 공개(체크) · 삭제. 입력·기대 출력은 고정폭 textarea(자동 높이), 탭·줄바꿈 그대로. 행 추가 버튼 + **여러 케이스 붙여넣기**(입력·출력 쌍을 `---` 구분자로 한 번에)는 후속
- 제한: 시간(초, 소수 허용, 기본 2) · 메모리(MB, 기본 256) - 서버가 내려준 기본값·상한(`defaultTimeLimitMs`, `maxTimeLimitMs`...)을 표시, FE 하드코딩 금지. Java·Python 문제는 시간을 늘리라는 한 줄 안내
- **정답 코드 상자**(언어 셀렉트 + CodeMirror): 두 버튼
  - "기대 출력 채우기" → #49 `inputs = 표의 입력들`, `expectedOutputs = null` → 각 행의 기대 출력에 stdout 을 채움(비어 있는 행만 채우고, 이미 값이 있으면 덮어쓸지 확인)
  - "출제 검증" → #49 `expectedOutputs = 표의 기대 출력들` → 행마다 ✅/❌ + 시간·메모리 표시. 하나라도 ❌ 면 저장 버튼 옆에 경고(저장은 막지 않음 - 의도된 어려운 케이스일 수 있음)
  - 정답 코드는 저장하지 않는다(서버에 정답 소스 열 없음) - 세션 초안(`lib/draft`)으로만 보존
- 저장(#48): 기존 제출이 있으면(`affectedSubmissions > 0`) 확인 창 "코드 제출 N건을 새 테스트케이스로 다시 채점할까요?" → 예 = `rejudge: true` 로 재요청, 아니오 = 그대로 저장. 응답 `rejudgeQueued` 를 토스트로
- 미리보기: 표 아래 "학생에게 보이는 예시" 접힘 - 공개 체크된 케이스만 예시 블록으로 렌더(2절과 같은 컴포넌트)
- 빈 상태(케이스 0개): "테스트케이스를 추가하면 자동 채점 문제가 됩니다. 없으면 제출만 받는 과제예요."
- **"이 표가 곧 채점 기준" 을 화면에서 반복해 알린다** *(2026-09-15, 운영 첫 사용 피드백 - 기대 출력을 비운 채 저장해 모든 제출이 틀렸습니다로 나온 사고)*
  - 표 제목 "테스트케이스 (채점 기준)", 열 머리글 "입력 (표준 입력)" · "기대 출력 (정답)"
  - 표 위 한 줄: "한 행이 채점 1회예요. 왼쪽 입력을 표준 입력으로 넣고 실행한 출력이 오른쪽 기대 출력과 같아야 통과합니다. 줄 끝 공백과 마지막 빈 줄은 무시해요."
  - 기대 출력이 빈 행: 테두리 강조 + "비어 있음 - 지금 저장하면 아무것도 출력하지 않아야 통과해요"
  - 저장 직전 확인 창(빈 케이스 N개 안내, 취소하면 폼 복귀) - **차단하지 않는다**: 출력이 없는 것이 정답인 문제도 있을 수 있어 판단은 출제자 몫
  - 용어는 "기대 출력" 유지(API 필드 `expectedOutput`·문서와 일치), 괄호로 맥락만 덧붙임
- 보관 분반: 섹션 읽기 전용(서버 409 방어와 별개)

## 2. 학생 - 과제 상세(`AssignmentDetailPage`)

- 헤더 배지: `judgeEnabled` 면 "자동 채점" + 시간·메모리 제한 표시(`GET .../judge/samples` 의 값)
- 예시 절: 공개 케이스를 "예시 입력 1 / 예시 출력 1 ..." 블록(고정폭, 복사 버튼)으로 - #50. 케이스 0개면 절 자체 없음
- 제출 폼: 자동 채점 문제면 코드 탭이 기본 선택 + 안내 "코드 제출은 자동 채점돼요. zip·링크는 운영진이 확인합니다". 언어 셀렉트는 6종 그대로(서버 미지원 언어면 400 메시지 그대로 표시)
- 제출 직후: 내 제출 기록 맨 위 행이 "채점 중"(스피너) → #20 을 2초 폴링(`status` 가 `DONE/ERROR` 되면 중단, 최대 3분 뒤에는 "새로 고침" 안내) → 배지로 바뀜

## 3. 채점 결과 표시 (학생·운영진 공용)

- 판정 배지(서버 `verdict` 그대로 매핑 - 재계산 금지)

| verdict | 표시 | 색 |
|---|---|---|
| `ACCEPTED` | 맞았습니다 | 초록 |
| `WRONG_ANSWER` | 틀렸습니다 | 빨강 |
| `TIME_LIMIT` | 시간 초과 | 주황 |
| `MEMORY_LIMIT` | 메모리 초과 | 주황 |
| `RUNTIME_ERROR` | 런타임 에러 | 빨강 |
| `COMPILE_ERROR` | 컴파일 에러 | 회색 |
| `JUDGE_ERROR` | 채점 오류 - 운영진에게 알려 주세요 | 회색(점선) |
| status `PENDING/RUNNING` | 채점 중 | 스피너 |
| `judge: null` | (표시 없음 - 채점 대상 아님) | - |

- 내 제출 기록 표: 지각 열 뒤 "채점 결과" 열(submission/design.md 결정 15 의 예약 자리) = 배지 + `N/M`(통과 케이스). 행 펼침(`SubmissionDetailView`)에 결과 상세
- 결과 상세(펼침 뷰, 코드 아래 · 코멘트 위): 요약 줄(배지 · 통과 N/M · 최대 시간 ms · 최대 메모리 KB · 채점 시각) + 케이스 표(`#` · 판정 · 시간 · 메모리). 공개 케이스 행은 펼쳐서 입력/기대 출력/**실제 출력** 나란히(diff 는 후속), 비공개는 판정만. `COMPILE_ERROR` 면 컴파일 메시지 블록. `JUDGE_ERROR` 면 "채점 서버 문제 - 재채점 요청" 안내
- 현황판(운영진): 상태 열 옆 "판정" 열 = 최신 제출 배지(`latestVerdict`) - 미제출·채점 대상 아님은 `-`. 상단 요약 "맞았습니다 X / 제출 Y / 전체 Z명"
- 과제 목록(학생·운영진): 자동 채점 과제에 작은 "자동 채점" 표시. 내 판정 배지는 후속(목록 API 확장 필요 - api.md 2절 외)

## 4. 표시 규칙

- 모든 판정·시간·메모리·통과 수는 서버 값 그대로(FE CLAUDE.md 규칙 4). "채점 중" 여부도 `status` 로만
- 폴링은 화면에 보이는 제출(펼친 행·최신 행)만, 탭이 숨겨지면 중단(`document.visibilityState`)
- 채점 결과가 없어도 제출은 성공 - 제출 성공 토스트와 채점 배지를 섞지 않는다("제출됐어요. 채점 중...")
- MSW: `judge` 핸들러 5개 + 제출 시 가짜 채점(1.5초 후 `DONE`, 정답 코드 문자열 포함 여부로 판정) - BE FakeJudgeEngine 과 같은 규칙으로
