# 6. Q&A 게시판 - 질문 글 CRUD만 P1 편입 (결정 4 일부 갱신)

- 날짜: 2026-09-09 · 상태: 확정 (BE 구현 완료 - ondal-BE PR #21)

## 결정

- Q&A 게시판을 **질문 글 CRUD 범위로 축소해 P1에 편입** - BE `qna` 슬라이스, API `/api/cohorts/{cohortId}/questions` 5개(#23~#27)
- 답변(댓글)·알림은 계속 백로그 - 결정 4의 "P3 재검토"는 이 두 항목에만 남는다
- 디스코드 스레드 대안은 폐기 아님 - 답변은 당분간 디스코드에서, 질문의 기록·검색은 Ondal에서

## 근거

1. **이미 만들어진 코드가 있었다**
   - 팀원이 학습 슬라이스로 게시판 CRUD를 구현(BE 이슈 #20 → PR #21). 독립 프로젝트 형태라 그대로는 못 쓰지만, 규약대로 재작성하는 비용이 크지 않았음
   - 버리는 것보다 규약을 지킨 슬라이스로 남기는 편이 팀 학습에 유리 - `assignment/` 패턴 복제 사례가 하나 더 생김
2. **범위 축소로 결정 4의 제외 사유가 대부분 해소**
   - 제외 사유 = "글·댓글·알림·권한 = 화면 3~4개". 댓글·알림을 빼면 남는 화면은 목록·작성/수정 2개
   - 권한은 기존 4단계 판정 + 서비스 판정(작성자 본인·운영진)으로 새 개념 없이 처리
3. **분반 스코프 원칙과 맞물린다**
   - guide/design.md 4절이 이미 "학생은 자기 분반의 과제 관련(+ 향후 Q&A·분반 공지)만 접근"으로 Q&A를 예고
   - 글은 분반에 속하고 작성자가 있어야 권한이 성립 - 전역 게시판이 아니라 분반 게시판

## 감수하는 것

- 답변이 없는 게시판 - 운영진 답은 디스코드 또는 후속 Answer 엔티티. "물었는데 여기서 답이 안 보이는" 상태가 당분간 존재
- BE만 먼저 있고 FE 화면은 미구현 - FE 이슈로 별도 진행 ([qna/fe.md](../qna/fe.md))
- 결정 4 문서와 BE CLAUDE.md의 "P1 제외" 문구는 이 문서로 갱신 - 결정 4는 원문 유지 + 갱신 주석

## 재검토 조건

- 답변 기능 요구 확인 시: `qna` 패키지에 `Answer` 엔티티(질문 N:1, 작성자, 내용) 추가 - 질문 삭제 시 서비스 연쇄, 권한은 질문과 동일 규칙
- 알림: P2 디스코드 알림 계획과 함께 - 새 질문 → 운영진 채널 알림
- 검색·페이징: 분반당 질문 수가 화면 한 장을 넘기기 시작할 때 (P1 목록 페이징 없음 규약)
