# 11. HOJ 문제 - 난이도 5×5·허용 언어·번들 가져오기·비공개 레포

- 날짜: 2026-09-19 · 상태: 확정 · 결정자: PM
- 관련: BE ondal-BE #51 (V9) · FE ondal-FE #74 · 레포 [ondal-problems](https://github.com/KNU-HAEDAL-Website-v3/ondal-problems) (비공개) · [judge/design.md](../judge/design.md) 결정 7·17 · [permissions.md](../permissions.md)

## 결정

- **부트캠프용 예시 문제 100개**를 만든다 - 백준 골드 3 수준까지, 알고리즘 문제와 **언어별 특화 문제**를 섞는다. 본문은 전부 자작(다른 사이트 본문 복제 금지)
  - 구성: 언어 특화 40 (C언어 12 · Python 12 · Java 8 · JavaScript/TypeScript 8) + 알고리즘 60. 난이도 계획 1-x 30 · 2-x 45 · 3-x 25 → **실제 1-x 14 · 2-x 50 · 3-x 36** (3-4·3-5 = 골드 3~4 수준 14문제, 부트캠프 후반용)
  - 현재 트랙: C, 파이썬, 웹기초(html·css), 바이브 코딩, Spring, Flutter, 알고리즘 - 지원 언어 6종은 그대로
- **난이도는 열로** (`problems.difficulty`, V9): 1~25 정수. 표기는 **"대분류-소분류"(1-1 ~ 5-5)**, 둘 다 클수록 어려움, 값 = (대분류-1)×5 + 소분류. 백준 브론즈 = 1-x, 실버 = 2-x, 골드 = 3-x. 4·5 는 이후 어려운 문제용
  - 태그로 난이도를 표현하지 않는 이유: 태그 필터가 난이도로 오염되고, P3 티어 시스템이 이 값을 쓴다
- **문제별 허용 언어** (`problems.allowed_languages`, V9): 언어 특화 문제에만 건다. 걸린 문제는 그 언어로만 제출 가능 - 과제 제출·HOJ 연습 제출 둘 다 서버가 400, FE 는 선택지를 좁힘. judge/design.md 결정 7 "과제별 허용 언어 제한 없음"은 유지 - 문제별 제한만 추가
  - 언어 특화 문제 태그: `C언어` · `Python` · `Java` · `JavaScript` 를 반드시 붙인다
- **본문은 마크다운** - 입력·출력 형식 표와 코드 블록이 필요. FE 는 react-markdown(HTML 미렌더)
- **번들 가져오기** `POST /api/problems/import` (`@AdminOnly`): 문제 번호가 키, 같은 번호는 `overwrite` 에 따라 덮어쓰기/건너뛰기, 태그 이름은 없으면 생성, 테스트케이스는 통째 교체(재채점 없음), 한 트랜잭션. 관리자 HOJ 화면 "문제 가져오기"로 JSON 업로드 - 운영은 OIDC 세션이라 스크립트로 넣을 수 없다. 번들이 약 10MB 라 FE 가 번호순 **10문제씩 나눠** 보낸다(묶음마다 트랜잭션, 도중 실패 시 어디까지 저장됐는지 안내 - 같은 파일을 다시 올리면 건너뛰기로 이어짐, FE #76)
- **저장은 새 비공개 레포 `ondal-problems`** - 문제마다 `meta.json` · `problem.md` · `gen.py`(입력 생성) · `solutions/`(정답 2개 언어 이상) · `tests/`(생성 산출물). `tools/gen.py → verify.py → build.py` 가 `dist/bank.json` 을 만든다
  - 새 레포인 이유: **3개 레포가 전부 public** 이라 비공개 테스트케이스·정답 코드를 둘 수 없다. 데이터(수백 파일)라 코드·문서 레포와 리뷰 주기도 다르다
- 번호 체계: HOJ 레포 문제는 **2001 부터** - 운영에서 운영진이 직접 낸 문제(1000번대)와 겹치지 않게

## 보완 (2026-09-19 밤) - 깃허브에서 직접 가져오기

- PM 질문: "문제를 어차피 깃허브 레포에 만들 거면 레포에서 바로 가져오면 되지, 왜 파일을 따로 만드나" → 맞는 지적. 파일 업로드는 비공개 레포 토큰이 없어도 되는 임시 경로였음
- **`POST /api/problems/import/github`** (`@AdminOnly`): 서버가 GitHub API 로 레포 ref 의 zip 을 받아 `problems/*/{meta.json, problem.md, tests/}` 를 읽고(`ProblemBankZipReader` = `tools/build.py` 규칙) 번들 가져오기와 같은 `ProblemImportService` 로 넣는다. 결과에 커밋 SHA
  - 설정 `ondal.problem-bank.github.{repo, ref, token}` - 토큰은 그 레포만 읽는 fine-grained PAT(Contents: Read-only), 서버 `.env` `PROBLEM_BANK_GITHUB_TOKEN`. 없으면 `GET /api/problems/import/github` 가 `configured=false` → 화면은 파일 업로드만 안내, POST 는 503 `PROBLEM_BANK_NOT_CONFIGURED`
  - zipball 의 302(서명된 codeload 주소)는 자동으로 따라가지 않고 Location 을 읽어 **토큰 없이** 받는다 - Authorization 이 다른 호스트로 새지 않게
  - 200문제씩 트랜잭션 - 그 이상은 묶음 단위(파일 경로의 FE 10문제 분할과 같은 성질)
  - **비동기 작업 + 상태 폴링** (2026-09-19 밤 2차): 첫 운영 시도에서 화면이 "서버에 연결할 수 없습니다"만 보임 - 수 초~수십 초 걸리는 요청은 프록시(nginx 60초·Cloudflare 100초)가 끊거나, Spring 밖에서 만들어진 오류 응답(500 등)에 CORS 헤더가 없어 브라우저가 원인을 못 봄. 그래서 POST 는 작업을 한 스레드에서 띄우고 202 로 상태만 돌려주며(`ProblemBankSyncStatus` - 단계·진행 수·받기/넣기 시간), 화면은 `GET /api/problems/import/github/status` 를 1.5초마다 폴링. 실패는 상태의 `error`(코드·원인)로 남긴다 - GitHub 오류 `PROBLEM_BANK_FETCH_FAILED`(토큰 만료·권한·레포 없음), 규칙 위반 `INVALID_INPUT`(문제 번호 표시), 그 밖의 예외·Error 도 문구로. 동시에 하나만(두 번째는 409), 상태는 메모리(재시작하면 IDLE)
- 화면 "문제 가져오기": **깃허브에서 가져오기(기본)** - `repo@ref` 표시, 버튼 하나 / 파일 업로드는 보조로 남김. 덮어쓰기 체크는 공통
- 레포 쪽: `tools/build.py` 는 로컬 확인용으로만, `dist/bank.json` 은 더 이상 운영 반영 경로가 아님. verify 통과 → PR 머지 → 관리자가 버튼 → 끝

## 검증 흐름

1. `python tools/gen.py <번호>`: `gen.py::cases()` 의 입력을 `solutions/sol.py` 에 넣어 `.out` 생성 (sol.py 가 기준)
2. `python tools/verify.py`: 다른 언어 정답(C 등)이 전부 같은 출력인지 확인 - 로컬에 있는 컴파일러만
3. PR 머지 → 관리자가 HOJ "문제 가져오기 → 깃허브에서 가져오기" (`python tools/build.py` → `dist/bank.json` 파일 업로드는 토큰이 없을 때의 보조 경로)
4. 운영 Judge0 로 표본 5문제 정답 제출 → Accepted 확인 (Python·Java 시간 제한 점검)
