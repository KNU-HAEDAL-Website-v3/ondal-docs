# 12. 관리자(MAINTAINER) 전역 역할 - 해구르르와 같은 권한, 다른 이름

- 날짜: 2026-09-19 · 상태: 확정 · 결정자: PM
- 관련: [permissions.md](../permissions.md) 1·2·4절 · [db/schema.md](../db/schema.md) V10 · [결정 3](3-%EA%B6%8C%ED%95%9C-%EB%AA%A8%EB%8D%B8-2%EC%B8%B5-%EA%B5%AC%EC%A1%B0.md) 2층 구조

## 배경

- PM(유지보수 팀)은 해구르르(동아리 임원)도, 교육운영진도, 부트캠프 수강생도 아님. 그런데 시스템 관리에는 해구르르와 같은 권한이 필요
- 기존 전역 역할은 `ADMIN`(해구르르) · `MEMBER` 둘뿐 → 유지보수 팀을 ADMIN 으로 두면 화면·명부에 "해구르르"로 표시돼 동아리 직책과 섞임

## 결정

- `users.global_role` 에 **`MAINTAINER`** 추가 (V10 - 허용값 `ADMIN` · `MAINTAINER` · `MEMBER`). 표시 명칭은 **"관리자"**, 해구르르는 "해구르르"로만
- **권한은 ADMIN 과 완전히 같다** - BE `User.isAdmin()` 이 둘 다 true. `@AdminOnly` · `@OperatorAnywhere` · `@CohortRole` · canEdit/canDelete 전부 그대로 통과, 별도 분기 없음
  - 코드 규칙: BE 는 `GlobalRole` 값을 직접 비교하지 않고 `isAdmin()` 만, FE 는 `lib/roles` `isAdminRole()` 만 (직접 비교 24곳 치환)
- 직책 표시(`RoleTitle`): MAINTAINER 면 어느 분반에서든 "관리자" → ADMIN 이면 "해구르르" → 분반 OPERATOR 면 "교육운영진" → 나머지 "일반 수강생"
- 지정 방법: 부트스트랩과 같은 수동 SQL - `UPDATE users SET global_role = 'MAINTAINER' WHERE login_id = '<loginId>';` (대상 한두 명이라 화면 없음)
- 로컬 시더 · FE mock 계정: `maintainer` / 유지보수

## 하지 않는 것

- ADMIN 보다 높거나 낮은 권한 - 필요해지면 그때 `isAdmin()` 을 둘로 나눈다
- 역할 변경 화면 - 대상이 극소수라 SQL 로 충분

## 검증

- BE `MaintainerRoleApiTest`: `/api/auth/me` → `MAINTAINER`, 분반 생성 · 태그 등록 · 번들 가져오기(`@AdminOnly`) · 부원 승인(`@OperatorAnywhere`) 통과, 분반 응답 `myTitle` "관리자"
- FE mock: `maintainer` 로그인 → 분반 관리 · 부원 관리 · 태그 관리 · 문제 가져오기 노출, 상단 바 · 마이페이지 · 부원 목록에 "관리자" 표시, `admin` 은 "해구르르"
