## 1. 범위

- 공지 글 CRUD API 6개 (`notice` 패키지) - **전체 공지**(관리자, 로그인한 누구나 열람)와 **분반 공지**(그 분반 운영진 이상, 소속자·관리자 열람)
- 범위 밖: 예약 게시·숨김(초안)·댓글·읽음 확인·첨부. 알림(디스코드)은 P2 별건 - 도입 시 공지 등록 이벤트가 후보
- FE 견본 화면(피그마 2:37234)의 "예약됨 / 숨김" 상태 열·기간 필터는 구현하지 않음 - 요구 없는 상태 모델을 만들지 않는다

## 2. 결정

1. **한 테이블, `cohort_id` NULL = 전체 공지** - 학생 화면이 "전체 공지 + 내 분반 공지"를 한 목록으로 보므로 한 쿼리로 받는 편이 단순. 전역/분반 테이블 분리 기각
2. **쓰기 권한 = 관리 권한, 작성자 무관** - 전체 공지: ADMIN / 분반 공지: 그 분반 운영진 이상(ADMIN 포함). `canEdit == canDelete`
   - Q&A(수정은 작성자만)와 다른 이유: 공지는 운영진 팀이 함께 관리하는 글 - 작성자가 자리를 비워도 고쳐야 함
3. **경로** - 공지 id 는 전역 → `/api/notices/{id}`. 분반 공지 **등록만** `/api/cohorts/{cohortId}/notices`: `@CohortRole` 이 소속을 판정하려면 경로에 `{cohortId}` 가 필요. 수정·삭제는 경로에 분반이 없어 `@LoginOnly` + 서비스에서 `CohortAuthorizer` 판정(403) - 권한 규약 (c) 는 경로에 `{cohortId}` 가 있을 때만 적용되므로 규약 위반 아님
4. **목록 가시성은 서버 판정** - 관리자: 전부 / 부원: 전체 공지 + 소속 분반 공지(보관 분반 포함 - 열람 유지). 프론트가 필터하지 않는다
5. **비소속의 분반 공지 상세 = 403** - 분반 GET 규칙과 동일. 같은 반 글은 누구나 보므로 존재 비노출(404)이 성립하지 않음
6. **정렬: 필독(`pinned`) 먼저 → 최신순 → id desc, 페이징 없음** - 공지 수가 적고, 학생은 스크롤 한 번으로 다 본다
7. **`pinned`(필독)만 상태값** - 목록 최상단 고정 + FE "필독" 배지. 예약·숨김 없음(1절)
8. **수정 시각 열 없음** - Cohort·Assignment·Question 과 동일. "수정됨" 표시가 필요해지면 열 추가
9. **보관 분반의 공지는 열람 유지, 쓰기 409 `COHORT_ARCHIVED`** - `ensureActive()` 규약. 전체 공지는 분반 상태와 무관
10. **인덱스 2개 명시** - `(cohort_id, created_at)` + `author_id` (PostgreSQL 은 FK 인덱스 자동 생성 없음)
11. **시더에 샘플 2건** - 전체 공지(관리자, 필독) 1 + 분반 공지(operator1) 1. FE mock 은 동일 데이터
12. **빈 소속의 IN 절 회피** - 소속 없는 부원은 존재하지 않는 분반 id 하나(-1)로 바꿔 넘긴다 (Hibernate 빈 컬렉션 IN 의존 회피)
