## 2. 확인했으나 문제 없던 것

- **N+1 없음** - 목록 경로가 전부 fetch join + 메모리 그룹핑 (cohort·attendance·notice·qna·problem·submission)
- **인덱스** - 목록 쿼리 접두사 전부 커버. V7 이 컬럼을 drop 하며 stale 인덱스도 함께 정리, `attendances` 는 `uk_attendances_session_user` 가 session_id 접두 역할
- 목록 응답에 코드 전문 미포함 (`SubmissionSummary`)
- `FileStorage` - 서버 생성 UUID 키, 경로 traversal 불가
- `GlobalExceptionHandler` - 내부 정보 미노출(내부 로그 + 일반 메시지 응답)
- CORS - 명시 오리진 + `allowCredentials`, 와일드카드 없음
- actuator - 404
- 로딩·에러·빈 상태 - 23개 페이지 전부 처리
- 페이지 안쪽 그리드 - 이미 전부 반응형(`sm:grid-cols-*`). 모바일을 막고 있던 것은 셸 하나뿐
- BE TODO/FIXME - 0건

## 3. 남은 부채

### 🟡 상태색이 의미별로 통일돼 있지 않음

- 같은 "지각" 배지인데 텍스트색이 화면마다 다름 - `#854d0e`(출석 배지·운영진 명부) vs `#b45309`(학생 뷰·운영진 요약)
- 위험/오답 텍스트가 `#ba1a1a`(= `--destructive` 토큰값)와 `#dc2626` 공존
- 위험 배경 4종(`#ffdad6` `#fee2e2` `#fef2f2` `#fecaca`), 경고 텍스트 5종·배경 4종
- 하드코딩 hex 58건 / 20개 파일 - 토큰을 경유하지 않음
- **처리 방향**: 의미별 1값 확정(위험은 기존 `--destructive` 재사용) → `index.css` 시맨틱 토큰 → 상태별 bg/text 쌍을 한 곳에서만 정의 → 배지 계열부터 치환

### 🟢 다크 모드는 사장 코드

- `index.css` 에 `.dark` 토큰 블록이 있으나 **`dark` 클래스를 붙이는 코드가 없음** - 토글 자체가 불가능
- 즉 하드코딩 색이 "다크에서 깨진다"는 것은 **현재로선 사실이 아님** - 다크가 없음
- **처리 방향**: 다크를 지원할지 먼저 결정. 안 할 것이면 `.dark` 블록과 `@custom-variant dark` 를 지워 사장 코드를 정리

### 🟢 페이징 전무

- BE 전체에 `Pageable`·`Page`·`Slice` **0건** - 모든 목록이 무제한 `List` 반환, 상한·커서도 없음
- 현 규모(분반 30~60명)에서는 무해
- 최초 병목 예상 1순위 = `GET /api/problems`
  - 분반 무관 전역 누적이라 유일하게 상한 없이 증가 / `left join fetch p.tags` 로 전건 + 태그 전건 적재 / HOJ 첫 화면이라 호출 빈도 최고 / FE 도 전량 렌더
  - 2순위 `GET /notices` 관리자 경로, 3순위 분반 Q&A 목록
- **처리 방향**: 응답 모양을 FE `api/types.ts` 와 함께 확정 → `GET /api/problems` 부터(기본 size 50, `problemNo asc`, 태그 AND 필터와 동시 동작 확인)
